# 9. Conventions & Maintenance

## 9.1 Getting started

```bash
cp .env.example .env.local     # fill AUTH_SECRET (npx auth secret) and others
npm install
npm run dev                    # http://localhost:3000, backend expected on :9090
```

| Script | Does |
|--------|------|
| `npm run dev` | Dev server (also rewrites `AGENTS.md` — see 9.4) |
| `npm run build` / `start` | Production build / serve |
| `npm run lint` | ESLint (next core-web-vitals + typescript) |
| `npm run typecheck` | `tsc --noEmit` |
| `npm run format` | Prettier on `**/*.{ts,tsx}` (with Tailwind class sorting) |

## 9.2 Environment variables

| Variable | Side | Required | Purpose |
|----------|------|----------|---------|
| `NEXT_PUBLIC_API_URL` | client | yes | REST base URL used by the browser |
| `NEXT_PUBLIC_SOCKET_URL` | client | no (falls back to API URL) | Socket.IO base URL |
| `API_URL` | server | no (falls back to public URL) | REST base for Auth.js server calls (e.g. internal network) |
| `AUTH_SECRET` | server | yes | Encrypts the session cookie |
| `AUTH_URL`, `AUTH_TRUST_HOST` | server | deploy-dependent | Auth.js host config |
| `AUTH_GOOGLE_ID`, `AUTH_GOOGLE_SECRET` | server | no | Enables Google sign-in |
| `NEXT_PUBLIC_FIREBASE_*` (+ `VAPID_KEY`) | client | no | Enables web push |

Public variables are validated by Zod in `lib/env.ts` at import time — a malformed
URL fails fast. `NEXT_PUBLIC_*` values are baked in at **build** time; changing them
requires a rebuild.

## 9.3 Code conventions

- **Formatting:** Prettier — no semicolons, double quotes, 2 spaces, width 80,
  trailing commas `es5`. Run `npm run format` before committing.
- **Imports:** `@/…` alias; group external → internal → relative.
- **Files:** kebab-case (`analysis-review.tsx`); services `<module>.service.ts`;
  schemas `<domain>.schema.ts`; contexts `<name>-context.tsx`.
- **Components:** named exports; `"use client"` only where needed (hooks, events,
  browser APIs). Pages and layouts stay server components.
- **Types:** no `any`; API shapes live in `types/api.ts`.
- **Strings:** never hard-code user-facing text — use translations.
- **Comments:** every file starts with a `/** … */` header saying what it is
  for (route files also list their URL and query params). Inside, comment the
  *why* of non-obvious logic, not the what. Keep headers true when you change a
  file. Don't write `*/` inside a block comment (e.g. `messages/*/x.json`): it
  closes the comment early.
- **Commits:** conventional style is used in history (`feat:`, `fix(admin):` …).

## 9.4 Next.js 16 caveats

- Request interception lives in **`proxy.ts`** (the old `middleware.ts` name).
- `params` and `searchParams` are **Promises** in pages/layouts — `await` them.
- `cookies()` / `headers()` are async.
- Always check `node_modules/next/dist/docs/` before using a Next API you remember
  from older versions. `AGENTS.md` is regenerated by `next dev`; commit it as is.

## 9.5 Pre-merge checklist

- [ ] `npm run typecheck` and `npm run lint` pass
- [ ] `npm run build` succeeds for changes to config, auth, or env
- [ ] New strings exist in **both** `en` and `ar`
- [ ] Checked in Arabic (RTL) and dark mode
- [ ] Mutations invalidate the right tags (lists update without reload)
- [ ] Loading, empty and error states handled
- [ ] Auth changes tested: expiry, refresh, sign-out, wrong role redirect
- [ ] Matching document in `docs/` updated

## 9.6 Debugging guide

| Symptom | Look at |
|---------|---------|
| Redirect loop / wrong home | `proxy.ts`, `ROLE_HOME`, session `error`/`needsCity` |
| Random sign-outs | `refreshSession()` result codes, `rotate.ts` de-dup, backend refresh TTL |
| 401 then success | Expected: baseQuery refreshed and retried |
| List not updating after mutation | `providesTags` / `invalidatesTags` mismatch |
| Chat not live | `status` from `useChatState()` (React DevTools → ChatProvider), `NEXT_PUBLIC_SOCKET_URL`, token in socket `auth` |
| No push | Firebase env vars, browser permission, `retinacare.pushOptOut`, service worker registered |
| Raw key shown instead of text | Missing translation key (often in `validation.json`) |
| Hydration warning on `<html>` | Theme class; `suppressHydrationWarning` is intentional there |

## 9.7 Known gaps / tech debt

- `README.md` is minimal; this folder is the real documentation.
- No automated tests yet. Good first targets: `lib/notification-link.ts`,
  `lib/auth/token-expiry.ts`, `lib/auth/token-store.ts`, Zod schemas.
- `rotate.ts` de-duplicates refreshes per server process only; with several
  server instances the backend's refresh-token grace period is what protects
  concurrent rotations.
